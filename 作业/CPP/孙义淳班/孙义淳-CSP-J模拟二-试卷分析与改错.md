## 三、逐题改错（推理 + 模拟全过程）

### 阅读·第1题 冒泡排序（16–23）

```cpp
// check(n, a)：对数组 a 做一趟"冒泡扫描"，返回本趟是否发生过交换
bool check(int n, int a[])
{
    bool found = false;                  // found：本趟是否发生交换，初值 false
    for (int i = 0; i + 1 < n; ++i) {    // 从左往右扫到倒数第 2 个元素（i+1<n 保证 a[i+1] 存在）
        if (a[i] > a[i+1]) {             // 若左边元素 > 右边元素（逆序对）
            found = true;                //   标记：本趟交换过
            auto temp = a[i];            //   交换 a[i] 与 a[i+1]（大数右沉、小数左浮）
            a[i] = a[i+1];
            a[i+1] = temp;
        }
    }
    return found;                        // 本趟结束，返回"是否交换过"
}

// solve(n, a)：反复整趟扫描，直到某趟无交换（数组已有序）——即冒泡排序
void solve(int n, int a[])
{
    while (check(n, a))                  // 只要上一趟还有交换，就再来一趟
        ;                                // 循环体是空语句（分号），什么都不做
}
```

**先懂程序在干什么**：
- `check`：一趟从左到右扫描，凡 `a[i] > a[i+1]` 就交换（小数左浮、大数右沉），并记 `found = true` 表示"本趟发生过交换"。
- `solve`：反复整趟扫描，直到某一趟**一趟都没有交换**（`found = false`）为止。
- 结论：这就是**冒泡排序**，结束时数组**升序**排列。

**破局点：逐行读懂后，哪几行是冒泡排序的命门？**

| 代码特征（看到什么） | 推理（这说明什么） |
|------|------|
| `if (a[i] > a[i+1])` 交换相邻两数 | 相邻元素比较，大数往右走 |
| `found = true` 记录"本趟交换过" | 一趟扫描有没有变动，有标记 |
| `while (check(n,a))` 反复整趟调用 | 扫完一趟**没变动就停**（found=false） |
| 三行特征合起来 | **冒泡排序**：相邻交换 + 无交换即有序 |

**一句话破局**：见到"**相邻交换 + 一趟无交换即停**"＝冒泡排序，结果必升序。
- 见"相邻交换"即排除选择/插入/归并（它们不是只换邻居）。
- 见"while 直到无交换"即确定是冒泡——因为冒泡的结束条件就是"某趟零交换"。

**逐行模拟法**（做题时在草稿纸上这样写）：
1. 抄下输入数组，标出 `found`、`i` 两个变量。
2. 每一趟 check：从左到右推 `i`，每遇逆序对就"划线交换"，同时 `found` 改 true。
3. 一趟结束看 `found`：true 则再来一趟；false 则停。
4. 数清共执行了几趟、交换了几次。

#### 第16题（错：答 T，正 F）
> solve 函数的 while 语句只写一份分号会产生语法错误（ ）

**推理**：`while (check(n, a))` 后面跟一个分号 `;`——分号本身是一条**空语句**（什么都不做），是合法的循环体。`while (条件) ;` 等价于 `while (条件) { }`，只是循环体为空。语法完全合法，不会报错。

**规范答法**：看到"语法错误"判断题，先想 C++ 语法规则——`;` 是空语句、合法。答 **F**。

#### 第17题（错：答 T，正 F）
> 当输入参数 n ∈ [0,1024] 时，solve 可能会进入死循环（ ）

**推理**：冒泡排序每趟扫描至少会把当前最大的元素"冒"到它最终位置。最多 n−1 趟后数组必然有序，有序后某一趟 `found` 必为 false，循环终止。任何输入（哪怕 n=0、n=1）都有限步结束，**不可能死循环**。

**逐行模拟**（n=5，输入 `a=[5,4,3,2,1]`，把每一趟 check 内部执行写全）：
```
solve(5, [5,4,3,2,1]) 进入
┌ 第1次 while 判断 → 调 check(5, a)
│  check: found=false
│   i=0: a[0]=5 > a[1]=4 ? 是 → found=true，交换 → [4,5,3,2,1]
│   i=1: a[1]=5 > a[2]=3 ? 是 → 交换 → [4,3,5,2,1]
│   i=2: a[2]=5 > a[3]=2 ? 是 → 交换 → [4,3,2,5,1]
│   i=3: a[3]=5 > a[4]=1 ? 是 → 交换 → [4,3,2,1,5]
│  return true（本趟交换过）
├ while 体（空语句）执行
┌ 第2次 while 判断 → 调 check(5, a)
│  check: found=false
│   i=0: 4>3 ? 是 → found=true，交换 → [3,4,2,1,5]
│   i=1: 4>2 ? 是 → 交换 → [3,2,4,1,5]
│   i=2: 4>1 ? 是 → 交换 → [3,2,1,4,5]
│   i=3: 4>5 ? 否
│  return true
├ while 体执行
┌ 第3次 while 判断 → check: [2,1,3,4,5]（交换 2 次）→ return true
┌ 第4次 while 判断 → check: [1,2,3,4,5]（交换 1 次）→ return true
┌ 第5次 while 判断 → check: 一趟扫描无任何交换 → found 保持 false → return false
└ while 条件为 false，循环终止
```
结论：逆序 5 个数共跑 **4 趟**（第 5 次 check 只用于判定终止），有限步结束 → **F**。

#### 第18题（错：答 T，正 F）
> 当 n=5，a = [1,2,3,4,5] 时，while 循环只运行一次（ ）

**推理**：`[1,2,3,4,5]` 已升序。`while` 是**先判断后执行**：第一次调用 `check`，整趟扫描发现没有任何 `a[i] > a[i+1]`，`found = false`，`check` 返回 false，循环体**一次都不执行**——运行 **0 次**，不是 1 次。

**逐行模拟**（n=5，输入 `a=[1,2,3,4,5]`）：
```
solve(5, [1,2,3,4,5]) 进入
┌ 第1次 while 判断 → 调 check(5, a)
│  check: found=false
│   i=0: 1>2 ? 否
│   i=1: 2>3 ? 否
│   i=2: 3>4 ? 否
│   i=3: 4>5 ? 否
│  return false（本趟无交换）
└ while 条件为 false → 循环体一次都没执行
```
结论：循环执行 **0 次** → **F**。

**关键区分**：`while(条件)` 与 `do...while` 不同！`do...while` 至少执行一次，`while` 可能 0 次。题目说"运行一次"→ 答 **F**。

#### 第19题（错：答 T，正 F）
> 当 n=5，a = [5,4,3,2,1] 时，while 循环运行两次（ ）

**推理**：见第17题模拟表——逆序 5 个数需要 **4 趟**（第 5 趟无交换用于终止）。不是两次。

**规范答法**：逆序 n 个数恰好需要 n−1 趟。n=5 → 4 趟。答 **F**。

### 阅读·第2题 二进制计数（24–30）

```cpp
// move(b, n)：把 b 当作 n 位二进制数（b[0] 是最低位），做一次"加 1"
bool move(int b[], int n)
{
    for (int i = 0; i < n; ++i) {        // 从最低位 b[0] 往高位扫
        if (b[i] == 1) { b[i] = 0; }     // 当前位是 1 → 置 0（相当于进位，继续看下一位）
        else { b[i] = 1; return true; }  // 当前位是 0 → 置 1，加 1 完成
    }
    return false;                        // 所有位都是 1 → 全部变 0，溢出归零
}

// print(n)：从全 0 开始，每次打印当前 n 位二进制，再 move 加 1，直到溢出
void print(int n)
{
    int b[n];
    for (int i = 0; i < n; ++i) b[i] = 0;   // 初始化全 0
    do {                                    // do-while：先打印一次，保证至少输出一行
        for (int i = 0; i < n; ++i) std::cout << b[i];  // 逐位输出 b[0]..b[n-1]
        std::cout << "\n";                  // 换行
    } while (move(b, n));                   // move 加 1；返回 false（溢出）时结束
}

// count(n)：数一数一共能加几次 1（即状态总数）
int count(int n)
{
    int b[100];
    for (int i = 0; i < n; ++i) b[i] = 0;   // 初始化全 0
    int c = 0;
    do { c++; } while (move(b, n));         // 每 move 成功一次 c 加 1
    return c;                               // 返回 2ⁿ
}
```

**先懂程序在干什么**：
- `move`：把 `b` 当 **n 位二进制数**，做一次"**加 1**"：从最低位 b[0] 起，逢 1 变 0（进位），遇到第一个 0 变 1 并返回 true；若全是 1（如 11…1），全部变 0 返回 false（溢出归零）。
- `print(n)`：从全 0 开始，`do...while` 先打印当前值、再 move 加 1，直到溢出。所以依次打印 `0, 1, 2, …, 2ⁿ−1` 的 n 位二进制。
- `count(n)`：数加 1 的次数 + 1，即状态总数 = **2ⁿ**。

**破局点：逐行读懂后，哪几行暴露了"加 1"？**

| 代码特征（看到什么） | 推理（这说明什么） |
|------|------|
| `for (i=0; i<n; ++i)` **从下标 0 起**扫 `b[]` | 从它开始扫 = **b[0] 是最低位**（最低位才第一个参与运算） |
| `if (b[i]==1) b[i]=0;` 且**继续下一位** | 当前位是 1 → 置 0 并**进位**（1+1=10，本位留 0） |
| `else { b[i]=1; return true; }` 遇 0 就停 | 当前位是 0 → 置 1 且**进位结束**（0+1=1，无需再进位） |
| 整个循环走完返回 false | 所有位都是 1 → 111…1 + 1 = 000…0 **溢出归零** |
| `do { 打印/计数 } while (move)` | 先输出当前状态、再 +1，反复 → **枚举 0,1,2,…,2ⁿ−1 全部状态** |

**一句话破局**：**"从最低位起，逢 1 置 0 继续、遇 0 置 1 即停"＝模拟二进制加 1**；外层反复调用＝从 0 数到 2ⁿ−1。
- 认出的关键不在"二进制"三字，而在**那段循环的形态**：它和十进制竖式加法"个位满十进一"是同一结构，只是基数换成 2——`b[i]==1` 就是"满 2"，置 0 就是"进一"。
- 一旦认出是"计数器加 1"：print 输出全部状态（共 2ⁿ 行）、count 返回值 = 2ⁿ、move 总工作量均摊 Θ(2ⁿ)——三个题全部迎刃而解。

**逐行模拟**（n=2，把 move 内部每一行执行写全）：
```
print(2) 进入：b=[0,0]（初始化全 0）
┌ do 第1次：打印 b[0]b[1] = 00
│  while 判断 → 调 move(b,2):
│    i=0: b[0]==1? 否 → b[0]=1, return true     ← 最低位 0 变 1，加 1 完成
│  b 变为 [1,0]
┌ do 第2次：打印 10
│  while 判断 → move:
│    i=0: b[0]==1? 是 → b[0]=0（进位）
│    i=1: b[1]==1? 否 → b[1]=1, return true     ← 次低位 0 变 1
│  b 变为 [0,1]
┌ do 第3次：打印 01
│  while 判断 → move:
│    i=0: b[0]==1? 否 → b[0]=1, return true
│  b 变为 [1,1]
┌ do 第4次：打印 11
│  while 判断 → move:
│    i=0: 1→0;  i=1: 1→0;  全 1 → return false   ← 溢出归零
└ while 条件 false → 结束
共打印 4 = 2² 行；count(2) 同理数到 4（第28题 → D）
```

#### 第24题（错：答 T，正 F）

### 阅读·第3题 公共子序列（31–37）

```cpp
const int mod = 1'000'000'007;           // mod：取模常数，防溢出
bool filled[maxn][maxn];                 // filled[i][j]：(i,j) 是否已算过（记忆化标记）
int mem[maxn][maxn];                     // mem[i][j]：f(i,j) 的结果缓存

// solve(i, j, a, b)：返回 a 前 i 个与 b 前 j 个的公共子序列个数（含空序列）
int solve(int i, int j, int a[], int b[])
{
    if (i == 0 || j == 0) return 1;      // 边界：有一边为空，只有空序列这 1 个
    if (filled[i][j]) return mem[i][j];  // 算过就直接返回缓存（记忆化）
    filled[i][j] = true;                 // 标记本格开始计算
    int sum = (solve(i-1, j, a, b) + solve(i, j-1, a, b)) % mod;  // 容斥：先加两半，再处理重复
    if (a[i] == b[j]) {                  // 若两序列末尾元素相等
        return mem[i][j] = sum;          //   f = f(i-1,j) + f(i,j-1)（重复项与新增项抵消）
    } else {                             // 若不相等
        return mem[i][j] = (sum - solve(i-1, j-1, a, b)) % mod;  //   f 再减去 f(i-1,j-1) 排除重复
    }
}
```

**先懂程序在干什么**：设 f(i,j) = a 前 i 个与 b 前 j 个的**公共子序列个数**（空序列算 1 个）。
- 边界：i=0 或 j=0，只能取空序列 → 1。
- 容斥递推：f(i,j) = f(i−1,j) + f(i,j−1) − f(i−1,j−1)，若 a[i]==b[j] 还要加上"以 a[i] 结尾的新子序列" f(i−1,j−1)，故：
  - a[i] == b[j] 时：f = f(i−1,j) + f(i,j−1)（两项中的 −f(i−1,j−1) 与 +f(i−1,j−1) 抵消）
  - a[i] != b[j] 时：f = f(i−1,j) + f(i,j−1) − f(i−1,j−1)（排除重复）
- `filled`/`mem`：记忆化，每对 (i,j) 只算一次。
- **功能 = 计算两个序列的公共子序列的数量**（第35题答案 B）。

**破局点：逐行读懂后，哪几行锁定"公共子序列计数"？**

| 代码特征（看到什么） | 推理（这说明什么） |
|------|------|
| 函数带两个下标 `(i, j)`、递归调 `(i-1,j)` 与 `(i,j-1)` | **二维递推**：状态是"两个序列各自的前缀"，即 DP 在序列对上做 |

### 完善·第1题 套餐限价（38–42）

```cpp
long long S[MAXN];                       // S：B 的前缀和，S[k]=B[0]+…+B[k-1]
long long solve(int N, int M, int L, int A[], int B[])
{
    std::sort(A, A + __(1)__);           // (1) = N：A 升序排序，区间 [A, A+N)
    std::sort(B, B + M);                 // B 升序排序
    S[0] = 0;                            // 前缀和首项
    for (int i = 0; i < M; ++i) S[i+1] = S[i] + B[i];   // 算 B 前缀和
    long long j = __(2)__;               // (2) = M：分界指针从最右端开始
    long long sum = 0;                   // sum：答案
    for (int i = 0; i < N; ++i) {        // 枚举每个主食 A[i]
        while (__(3)__ && A[i] + B[j-1] > L) { j--; }   // (3) = j > 0：向左收缩，直到 A[i]+B[j-1] ≤ L
        sum += (A[i] * __(4)__);         // (4) = j：合法饮料 j 个，各加一份 A[i]
        sum += S[__(5)__];               // (5) = j：加 B[0..j-1] 之和（前缀和 S[j]）
        sum += (M - j) * L;              // 剩余 M-j 个饮料超限，各按 L 收
    }
    return sum;                          // 返回总花费
}
```

**先懂算法骨架**：
- 把 A、B 都升序排序。对每个 A[i]，凡是 `A[i] + B[k] ≤ L` 的饮料按实际价，`> L` 的按 L 收。
- B 升序后，`A[i] + B[k] ≤ L` 对 k 是**前缀**性质：存在分界 j，使 B[0..j−1] 都满足、B[j..M−1] 都不满足。
- 对每个 A[i]：合法 j 个 → 花 `j 个 A[i] + B[0..j−1] 之和`；不合法 M−j 个 → 花 `(M−j)·L`。
- 指针 j 随 A[i] 增大**只减不增**（A 升序），故总 O(N+M)。

**破局点：逐行读懂后，哪几行是命门？**（完善程序同样先逐行注释、再抓关键行，最后填空）

| 代码特征（看到什么） | 推理（这说明什么） |
|------|------|
| 两处 `sort(...)` 把 A、B 排序 | 排序后数据有序 → 多半要用**单调性**做双指针/二分 |
| `S[i+1] = S[i] + B[i]` | 前缀和 → **区间和 O(1)** 可取，不用每次累加 |
| 指针 `j` 只在 `while` 里 `j--`（只减不增） | **双指针**：随外层 i 单调移动，总步数 O(N+M)，不是 O(N·M) |
| `A[i] + B[j-1] > L` 作为收缩条件 | 用"和超限"判断分界 → 在找**合法前缀的边界** |
| `(M - j) * L` 一段按统一价收 | 分界之后整段同价 → 用前缀和 + 乘法**批量计费** |

**一句话破局**：**"排序 + 前缀和 + 单指针单调移动 + 区间批量计费"＝双指针套路**（常见于计数、求和、区间划分）。
- 逐行读懂后填空全是送分：排序范围 (1)=N、指针初值 (2)=M、防越界 (3)=j>0、合法数量 (4)=j、前缀和取 (5)=S[j]。
- 双指针的**总复杂度 O(N+M)** 是它存在的意义——凡见 j 单调移动，先想到"均摊线性"。


**换你来写：如果这题让你自己写，你怎么写？**

### 完善·第2题 简单路径（43–47）

```cpp
// dfs(node)：从 node 继续枚举简单路径；每进入一个节点，cnt 增加一条"以该节点结尾"的路径
void dfs(int node)
{
    __(1)__;                    // (1) = cnt += 1：到达 node，新增一条路径
    if (cnt > limit) return;    // 超过 1024 条直接返回（不继续枚举）
    visited[node] = __(2)__;    // (2) = true：标记 node 已在当前路径中
    for (auto v : __(3)__)      // (3) = adj[node]：遍历 node 的邻居
    {
        if (not visited[v]) {   // 邻居 v 未在当前路径中，才能走
            dfs(__(4)__);       // (4) = v：递归进入邻居 v
        }
    }
    visited[node] = __(5)__;    // (5) = false：回溯时还原，允许其他路径再经过 node
}
// main 中调用：dfs(__(6)__);   // (6) = 1：从 1 号出发
```

**先懂算法骨架**：统计从 1 号出发的**简单路径条数**（点不重复）。DFS 回溯枚举：
- 每次进入 dfs(node)，代表"到达 node"形成**一条以 node 结尾的新路径** → `cnt += 1`。
- 进入 node 时标记 `visited[node] = true`（防止路径中重复走点）；回溯离开时恢复 `visited[node] = false`（允许其他路径再经过它）。
- 遍历邻接表 `adj[node]`，对未访问的邻居递归 `dfs(v)`。
- 入口从 1 号出发 → `dfs(1)`；超 1024 输出 −1。

**破局点：逐行读懂后，哪几行暴露"回溯枚举"？**

| 代码特征（看到什么） | 推理（这说明什么） |
|------|------|
| `for (auto v : __(3)__)` 遍历邻居 | 邻接表 `adj[node]` → **图遍历（DFS）**，非树/数组 |
| `visited[node] = __(2)__` 进点标、`__(5)__` 出点还 | 进入置 true、回溯置 false → **回溯**（普通 DFS 标记后不还原） |
| `if (not visited[v]) dfs(v)` 只走未访问点 | **简单路径**：路径中不重复走点 |
| 进函数先 `__(1)__` 计数 | 每到达一点记一条 → **统计路径条数**（进点即计数） |
| `if (cnt > limit) return` | 计数上限 → 题目要求"超 1024 输出 −1" |

**一句话破局**：**"visited 进点 true、回溯 false + 进点计数"＝DFS 回溯枚举路径条数**。
- 关键在 visited **回溯还原**：普通 DFS 找连通/可达只标不还，凡见到"回溯时还原标记"，必是**枚举所有方案**（路径、排列、子集）——这是回溯的标志性动作。
- 认出后填空即定：进点计数 (1)=cnt+=1、标记 (2)=true、还原 (5)=false、入口 (6)=1。


**换你来写：如果这题让你自己写，你怎么写？**

1. **先明确要算什么**：从 1 号出发的简单路径条数——路径上点不重复；超过 1024 条输出 −1。
2. **想算法**：图可能有环、点不能重复走，最自然的办法是带着"当前已走的点集合"去探索——走到一个点就标记它，把它的所有延伸走完后取消标记退回来，换下一条岔路继续。这正是 DFS 回溯；且每走到一个新点，就多出一条以它结尾的路径，计数 +1。（为什么不用 BFS？BFS 只适合求最短/可达，要把所有路径一条条数清，得回溯枚举。）
3. **对照题面代码**：dfs 函数就是第 2 步的直接翻译——进点计数、进 true 回 false、遍历邻居递归、入口 dfs(1)。亲手设计过一遍，这些空不需要背。

**第52题**（答 D，正 C）：r=1, b=5 时输出 .(0011)。手算：r=1→q=0,r=2；r=2→q=0,r=4；r=4→q=1,r=3；r=3→q=1,r=1（回到 1，循环开始）→ 商序列 0011 循环 → **C**。

**第53题**（答 C，正 B）：数组 mem 记录余数首次出现的位置。`mem[r] = step` 在余数首次出现时记录步数；`mem[r] > 0` 即余数重复 → 定位循环节起点 → **B**。

**第54题**（答 C，正 A）：最坏时间复杂度 Θ(b)。余数至多 b 种，循环至多 b 步（余数重复即停）→ **A**。

**第57题**（答 B，正 D）：(4)(5) 处填 a[i] > key 与 merge_sort(0, n+1)。中位数二分：`b[i]=1` 当 a[i] > key 否则 −1，前缀和 s 共 n+1 个（s[0..n]），统计"和 > 0"的正序对用 `merge_sort(0, n+1)`（含 s[0]）→ **D**。

**第59题**（答 A，正 D）：(7)(8)(9) 处填 end-begin、begin+length/2、end。主循环 length 是半开区间长度（end−begin），mid 用 begin+length/2（避免溢出）；不变式为 begin < 答案 ≤ end，收敛到 length=1 时 end = begin+1 = 答案，输出 **end** → **D**。区分点在 (9) 输出 end 而非 begin。

## 四、程序阅读做法（必读）

阅读程序题的核心：**先逐行看懂、再抓关键行、再模拟验证、最后按题型答题**。顺序不可颠倒——破局点是从逐行读懂里"长"出来的，不是扫一眼猜出来的；扫一眼猜错，满盘皆输。

### 第1步：逐行注释——把每行代码翻译成人话（2-3分钟，一切的基础）

拿到程序，**从第一行起逐行给代码写注释**。注释写变量**含义**（不是字面翻译），条件写**判断什么**（不是"如果成立"），动作写**为什么做**。看不懂的行先标"？"，读完一遍再回看。标准格式：

```
// check(n, a)：对数组 a 做一趟"冒泡扫描"，返回本趟是否发生过交换
bool check(int n, int a[])
{
    bool found = false;                  // found：本趟是否发生交换，初值 false
    for (int i = 0; i + 1 < n; ++i) {    // 从左往右扫到倒数第 2 个元素
        if (a[i] > a[i+1]) {             // 若左边 > 右边（逆序对）
            found = true;                //   标记：本趟交换过
            auto temp = a[i];            //   交换 a[i] 与 a[i+1]（大数右沉）
            a[i] = a[i+1];
            a[i+1] = temp;
        }
    }
    return found;                        // 返回"是否交换过"
}
```

逐行注释做完，每行干什么都清楚了，重点和关键自然浮现——下一步就是把它们挑出来。

### 第2步：找破局点——从逐行读懂的代码里抓关键行

回看刚注释完的代码，问自己："**哪几行是这段程序的命门？删掉或改动哪几行，整个程序就变了？**"把这几行关键代码挑出来，程序的功能就锁定了。

以本卷为例（各题详表见前文"破局点"小节）：

| 程序 | 逐行读完后浮现的关键行 | 锁定的功能 |
|------|------|------|
| 冒泡排序 | `a[i]>a[i+1]` 就交换＋`found` 记录本趟有无交换＋`while(check)` 到无交换为止 | 相邻交换、无交换即停＝冒泡，结果升序 |
| 二进制计数 | 从 i=0 扫起、`b[i]==1→置0` 继续、`b[i]==0→置1` 即停 | 与十进制竖式加法同构＝二进制加 1，枚举 0..2ⁿ−1 |
| 公共子序列 | 双下标递推＋边界 `return 1`（空序列算 1）＋末尾相等分支＋容斥减重 | 二维 DP 计数公共子序列 |
| 套餐限价 | sort＋指针 j 只减不增＋前缀和 S＋`(M-j)*L` 整段计费 | 双指针＋前缀和，O(N+M) |
| 简单路径 | visited 进 true 回溯 false＋进点计数＋只走未访问邻居 | 回溯枚举简单路径条数 |

**要点**：关键行不是猜的——是逐行注释后，靠"这行为什么存在"逼出来的。比如二进制计数题，只有逐行读过 `b[i]==1→置0继续 / ==0→置1即停` 的配合，才能认出它和竖式加法"满十进一"是同一结构。

### 第3步：手算模拟——拿小数据跑一遍（3-5分钟）

功能锁定后，对给定输入**逐行执行**，像电脑一样记录变量变化，验证理解。标准格式：

```
solve(5, [5,4,3,2,1]) 进入
┌ 第1次 while 判断 → 调 check(5, a)
│  check: found=false（扫描开始）
│   i=0: 5>4 ? 是 → found=true，交换 → [4,5,3,2,1]
│   i=1: 5>3 ? 是 → 交换 → [4,3,5,2,1]
│   i=2: 5>2 ? 是 → 交换 → [4,3,2,5,1]
│   i=3: 5>1 ? 是 → 交换 → [4,3,2,1,5]
│  return true（本趟交换过）
├ while 体（空语句）执行
┌ 第2次 while 判断 → 调 check(5, a) ...
```

**要点**：把每次交换/赋值后的数组或变量值**写下来**，不要心算。模拟与第2步的功能判断互相印证——对不上就回头重新读代码。

### 第4步：按题型答题（每种题型的固定套路）

**判断题**——看"必然/可能/一定/不一定"：**找反例**。只要有一个反例就答 F。
- 33 题：`solve(n,n,a,a)` 一定 2ⁿ？a=[1,1]→6≠4，反例 → F。
- 24 题：count 可能死循环？2ⁿ 有限步，无反例 → F。
- **口诀**：判断题不找依据，找反例。

**选择题**——看"一下说法正确的是/错误的是"：**算必然**，逐项排除。
- 35 题功能：先排除"长度/子串/简单计数"，剩下 B。
- 29 题复杂度：print 输出 n·2ⁿ 行 → Θ(n·2ⁿ)，count 均摊 Θ(2ⁿ)。

**输出题**——看"输出什么/第几行第几列"：**模拟结果直接读**。
- 27 题：先定行号对应数字（523→522），展开二进制，对齐列。

**复杂度题**——看"时间复杂度/最坏情况"：**数状态数**，不是数递归层数。
- 36 题：n×m 个状态，每格 O(1) → Θ(n·m)。
- 29 题 count：总操作量 = 所有位翻转次数之和 = Θ(2ⁿ)，不是 n·2ⁿ。
- **口诀**：递归+记忆化=数格子；计数器=算总翻转数。

**功能题**——看"主要功能是"：**排除干扰项后确认**。
- 排除"长度/子串/简单计数"等干扰项。
- 对照递推公式确认是"计数"还是"长度"。

## 五、程序补全做法（必读）

完善程序题的核心：**读懂算法骨架，把每个空补成让程序正确、自洽的代码**。

### 1. 先整体理解，再填空

补全前必须完成：
1. **读题干**——程序要算什么（套餐总花费、路径条数）。
2. **读完整代码**——看注释、看 main、看循环结构，先画"程序分几步"。
3. **标注变量角色**——每个数组、每个变量是干什么的：

| 题组 | 变量角色 |
|------|---------|
| 套餐限价 | A/B 排序数组、S 前缀和、j 分界指针、sum 答案 |
| 简单路径 | adj 邻接表、visited 访问标记、cnt 路径计数、limit 上限 |

4. **换位思考——如果让我写**：读罢题干，先合上题面代码自问"这个程序我会怎么写？用什么算法？"——哪怕先写出最笨的暴力，再想怎么优化；然后翻开题面代码对照。题面的每个空，本是你自己思路里的一步。


变量角色不清，填空必错（40 题 i/j 混淆、43 题 cnt 倍增/累加混淆）。

### 2. 填空技巧

- **按执行顺序逐空推**：从 main 第一个空开始，跟着数据流走（(2) 一定是入口指针初值）。
- **边界/终止条件先定位**：(3) 类填空基本是越界判断——访问 `arr[k-1]` 必先保证 `k > 0`。
- **数量 vs 下标**：A[i] 配的饮料个数是 j，不是 i（41 题）。
- **标记方向**：DFS 进入 true、回溯 false（44 题），方向反了会死循环。

### 3. 代入验证（最关键）

填完全部空后，**取小样例手跑一遍**，检查每步值是否合理：
- 套餐题：N=3, M=3 手算总花费 43，跑程序对 43 则自洽。
- 简单路径题：小图 1–2、1–3、2–4 手数 4 条路径。

**不要背套路模板**——每道完善程序的骨架都要靠现场逐行读懂题面代码得来；背出来的模板换个皮就失效，读懂的能力才迁移。
